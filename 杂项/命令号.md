# 1. 先把“命令号”搞明白

**命令号不是 TCP 自带的东西。**

它是你自己规定的。

比如你做一个聊天程序，可以规定：

```
#define CMD_ECHO   1
#define CMD_LOGIN  2
#define CMD_CHAT   3
#define CMD_EXIT   4
```

意思就是：

```
1 → 回显
2 → 登录
3 → 聊天
4 → 退出
```

假如客户端发送：

```
[长度][命令号][数据]
  5      1      hello
```

服务器收到以后：

```
先看命令号
     ↓
    1
     ↓
知道这是 CMD_ECHO
     ↓
把 hello 回给客户端
```

以后如果收到：

```
[长度][命令号][数据]
  5      3      hello
```

服务器看到：

```
命令号 = 3
```

就知道：

```
这是 CMD_CHAT
```

所以你可以把**命令号理解成“这条消息的用途标签”**。

------

# 2. 你现在已经解决的“长度”干了什么？

你前面做的是：

```
[长度][数据]
```

例如：

```
[5][hello]
```

长度解决：

> **“这一条消息到哪里结束？”**

命令号解决：

> **“这一条消息是干什么的？”**

于是就变成：

```
[长度][命令号][数据]
```

例如：

```
[5][1][hello]
```

翻译成人话：

```
这一条消息的数据长度是 5
命令是 1
实际内容是 hello
```

这就是你看到别人代码里的那个东西。

------

# 3. 为什么一定要“命令号”？

因为以后服务器不可能只有“收到什么就原样返回”。

比如以后你做一个真正的客户端/服务器：

客户端可能发：

```
登录
```

也可能发：

```
注册
```

也可能发：

```
查询用户
```

也可能发：

```
发送聊天消息
```

如果全部只是：

```
[长度][数据]
```

服务器看到：

```
hello
```

它不知道：

```
这是登录数据？
还是聊天数据？
还是查询数据？
```

所以增加：

```
命令号
```

就可以告诉服务器：

```
你该干什么
```

# 4. 你可以把整个数据包想象成“快递单”

这个比喻很适合你。

你现在设计一个网络数据包：

```
+------------------+
|  长度            |  ← 这包有多长
+------------------+
|  命令号          |  ← 这是干什么的
+------------------+
|  实际数据        |  ← 真正的内容
+------------------+
```

就像快递：

```
长度 → 包裹多大
命令号 → 这是退货件 / 普通件 / 加急件
数据 → 真正的东西
```

服务器拿到后：

```
先拆快递单
   ↓
看长度
   ↓
知道这一包结束在哪里
   ↓
看命令号
   ↓
知道自己要做什么
   ↓
处理实际数据
```

这就是协议。

# 7. `memcpy()` 到底是什么？

它非常简单：

> **把一段内存里的字节，原封不动地复制到另一段内存。**

比如：

```
char a[] = "hello";
char b[10];

memcpy(b, a, 5);
```

就是：

```
a：

h e l l o
↓ ↓ ↓ ↓ ↓

b：

h e l l o
```

它不懂：

```
这是字符串
这是网络包
这是命令号
这是 TCP
```

它什么都不懂。

它只干一件事：

```
内存 → 复制 → 另一块内存
```

------

# 8. 为什么网络代码特别喜欢 `memcpy()`？

因为网络数据本质上就是：

```
一堆字节
```

比如我们要构造：

```
[长度][命令号][数据]
```

假设：

```
长度 = 5
命令号 = 1
数据 = "hello"
```

我们可以准备一个大缓冲区：

```
char packet[1024];
```

然后把东西一个一个塞进去：

```
packet：

+----+----+----+----+----+----+----+----+----...
|长度 4字节|命令号4字节|    数据...
+----+----+----+----+----+----+----+----+----...
```

这时候 `memcpy()` 就特别方便。

# 10. `memcpy()` 就是“装箱”

你可以把它想象成：

```

packet
+----------------------+
|                      |
|                      |
|                      |
+----------------------+
```

先把长度放进去：

```
+----------------------+
|      长度            |
|                      |
|                      |
+----------------------+
```

```
+----------------------+
|      长度            |
```

```
+----------------------+
|      长度            |
|      命令号          |

+----------------------+
```

`memcpy()` 就是：

> **往指定位置复制字节。**

# 11. 例如这几句到底是什么意思？

```

```

你不要害怕。

拆开：

```
packet
  ↑
目标位置
```

```
&net_len
   ↑
要复制过来的东西
```

```
4
↑
复制4个字节
```

所以整句话：

```
把 net_len 里面的4个字节
复制到 packet 的开头
```

------

然后：

```
memcpy(packet + 4, &net_cmd, 4);
```

这里你之前学过：

```
packet + 4
```

表示：

```
从第5个字节的位置开始
```

所以：

```
packet
 ↓

[  长度  ][  命令号  ]
 0~3       4~7
```

`packet + 4` 就正好指向：

```

```

------

然后：

```

```

就是：

```
从第9个字节开始

```

所以：

```

↓        ↓        ↓
+--------+--------+---------+
| 长度   | 命令号 |  数据   |
+--------+--------+---------+
```

你看，这时候 `memcpy()` 的作用就非常直观了。

# 14. 客户端发送的时候，顺序非常重要

你刚才问：

> “我都混了，都不知道哪一步先做。”

我们现在就把顺序钉死。

客户端：

```
① 用户输入数据
       ↓
② 计算数据长度
       ↓
③ 准备命令号
       ↓
④ 把长度转换成网络字节序
       ↓
⑤ 把命令号转换成网络字节序
       ↓
⑥ 发送4字节长度
       ↓
⑦ 发送4字节命令号
       ↓
⑧ 发送实际数据
```

也就是：

```
客户端
   ↓
[长度]
   ↓
[命令号]
   ↓
[数据]
```

# 15. 服务端反过来

服务端：

```
① recv_exact() 收4字节
       ↓
② 得到长度
       ↓
③ recv_exact() 收4字节命令号
       ↓
④ 得到命令号
       ↓
⑤ recv_exact() 按长度收数据
       ↓
⑥ 根据命令号决定怎么处理
```

也就是：

```
服务端
   ↓
先收长度
   ↓
再收命令号
   ↓
再收数据
   ↓
switch(命令号)
   ↓
决定干什么
```

这就是你现在应该形成的脑图。

------

# 16. 最关键的一点：`recv_exact()` 仍然继续用！

千万不要觉得：

> “我学了命令号，所以前面的 `recv_exact()` 不用了。”

不是。

它们是叠加的。

例如：

```
                一个完整的数据包
                      ↓
        +-------------+-------------+
        |             |             |
      长度          命令号         数据
      4字节          4字节        N字节
        |             |             |
        +-------------+-------------+
               都通过 TCP 传
```

但是 TCP 可能把它拆成：

```
第一次 recv：
[长度的前2字节]

第二次：
[长度后2字节][命令号前1字节]

第三次：
[命令号后3字节][数据前2字节]

第四次：
[剩余数据]
```

不用怕。

因为你：

```
recv_exact(4)
```

会负责把：

```
长度
```

收完整。

然后：

```
recv_exact(4)
```

负责把：

```
命令号
```

收完整。

然后：

```
recv_exact(len)
```

负责把：

```
数据
```

收完整。

所以：

```
粘包/拆包问题
      ↓
recv_exact()
      ↓
每个字段都能完整取出来
```

# 17. 然后服务器就出现了一个非常重要的东西：`switch`

比如：

```
switch (cmd)
{
case CMD_ECHO:
    // 回显
    break;

case CMD_LOGIN:
    // 登录
    break;

case CMD_CHAT:
    // 聊天
    break;
}
```

现在你应该一下明白：

```
命令号
   ↓
switch
   ↓
决定程序走哪条路
```

所以**命令号本质上就是“告诉服务器执行哪个功能”。**
