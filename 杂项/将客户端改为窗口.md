> ### ✅ Windows GUI 程序入口修正标准流程
>
> 请严格按照以下顺序操作，**不要手动填写"入口点"参数**。
>
> #### 第一步：修改代码中的入口函数
>
> 将原来的 `int main()` 替换为 Windows GUI 标准签名：
>
> ```
> #include <windows.h>
>
> // ❌ 删除或注释掉原来的: int main() { ... }
>
> // ✅ 替换为标准 GUI 入口
> int WINAPI WinMain(HINSTANCE hInstance, HINSTANCE hPrevInstance, LPSTR lpCmdLine, int nShowCmd)
> {
>     // 把你原来 main() 函数体里的代码【原封不动】粘贴到这里
>     
>     return 0;
> }
> ```
>
> > **注意**：四个参数即使暂时用不到也必须保留，这是 Windows 规定的固定签名，少一个都会报错。
>
> #### 第二步：确认子系统设置
>
> 1. 右键项目 → **属性** → **链接器** → **系统**
> 2. 将 **子系统** 设置为：**Windows (/SUBSYSTEM:WINDOWS)**
>
> #### 第三步：清空入口点参数（关键！）
>
> 1. 右键项目 → **属性** → **链接器** → **高级**
> 2. 找到 **入口点** 输入框
> 3. **彻底清空它**（留空 = 让编译器自动匹配）
> 4. 点击应用/确定
>
> #### 第四步：重新生成
>
> - 菜单栏选择 **生成** → **重新生成解决方案**（不要用"生成"，用"**重新生成**"确保旧缓存被清除）
>
> ------
>
> ### 📋 自查清单
>
> 完成上述四步后，对照下表确认：
>
> | 检查项       | 正确状态                       | 错误状态                     |
> | ------------ | ------------------------------ | ---------------------------- |
> | 入口函数签名 | `int WINAPI WinMain(四个参数)` | `int main()`                 |
> | 子系统       | Windows (/SUBSYSTEM:WINDOWS)   | Console (/SUBSYSTEM:CONSOLE) |
> | 入口点参数框 | **空**                         | 填了任何内容                 |
> | 编译结果     | 0 Error, 0 Warning             | LNK2019 / LNK2001            |
>
> ### ⚠️ 如果仍然报错
>
> 按以下优先级排查：
>
> 1. **确认 WinMain 写在了全局作用域**，没有嵌套在其他函数或命名空间内
> 2. **确认字符集一致**：如果项目属性中"字符集"是 Unicode，则应使用 `wWinMain` + `LPWSTR`；如果是多字节/未设置，则用上面的 `WinMain` + `LPSTR`
> 3. **确认文件参与了编译**：右键该 `.cpp` 文件 → 属性 → "从生成中排除"应为 **否**
> 4. **清理重建**：菜单栏 → 生成 → 清理解决方案 → 再重新生成
>

> > 链接器 → 高级 → 入口点：**清空**
> >
> > > 💡 **本质理解**：Visual Studio 的"子系统"选项就是一个开关。选 Windows，编译器就自动找 `WinMainCRTStartup` → `WinMain`；选 Console，编译器就自动找 `mainCRTStartup` → `main`。**你从来不需要手动告诉编译器入口函数叫什么，它会根据子系统自动推导。** 手动填入口点 = 覆盖了这个自动推导机制，所以才会出现各种诡异报错。
> >

> >
> > 如果你从 GUI 切回控制台后发现 `printf` / `cin` / `cout` 没反应，大概率是上一步"清空入口点"没做干净，或者没有用"**重新生成**"而是用了普通的"生成"。务必执行一次 **清理解决方案 → 重新生成解决方案**。

### 🎯 一句话解释

`lpfnWndProc` 就是给窗口指定一个 **“专属客服”**。

------

### 💡 想象你开了一家餐厅（你的程序）

- **窗口** = 餐厅里的一个包间
- **消息** = 客人提出的各种需求（“点菜”、“加水”、“结账”、“打扫”）
- **lpfnWndProc** = 你分配给这个包间的 **服务员名字**

当你在注册窗口类时写下：

```
ws.lpfnWndProc = MyWndProc;
```

意思就是：**“以后这个包间里不管发生什么事，都叫 MyWndProc 这个服务员来处理！”**

------

### ❓ 如果不设置它会怎样？

就像包间里没有服务员一样——客人喊破喉咙也没人理。在程序里表现为：**窗口完全卡死，点不动、关不掉、不显示任何内容。**

------

### ✅ 萌新只需要记住3件事

1. **它是个函数名**：把你写的处理消息的函数名填进去就行
2. **必须填**：空着程序就跑不起来
3. **一个窗口类对应一个客服**：同一类窗口共用同一个处理函数

就这么简单！你现在只需要知道：**它是让你的窗口能“响应操作”的关键开关**，等你后面学到消息处理（`switch(msg)`）时，自然就明白这个“客服”具体是怎么工作的了。 😊
