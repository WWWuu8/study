# 04 服务端逐函数理解

## 1. 服务端的任务

服务器是“被控制端”，主要做三件事：

```text
① 接收客户端请求
② 截取自己的屏幕并发送
③ 接收鼠标键盘并执行
```

## 2. main 的执行顺序

```text
SetProcessDpiAwareness
        ↓
WSAStartup
        ↓
GDI+
        ↓
socket
        ↓
bind
        ↓
listen
        ↓
accept
        ↓
循环 recv_packet
        ↓
HandleCommand
```

## 3. create_listen_socket

这里一次完成：

```text
socket()
bind()
listen()
```

### socket

创建通信端点。

### bind

告诉系统：

```text
我要监听 8080
```

### listen

进入等待客户端连接状态。

## 4. accept_client

`accept()` 成功后：

```text
lfd
 |
 +--> 继续负责监听

cfd
 |
 +--> 专门和这个客户端通信
```

这是 Socket 编程最容易混淆的地方之一。

## 5. HandleCommand

它就是一个“分拣员”：

```text
cmd
 |
 +-- CMD_SCREEN --> HandleScreen
 |
 +-- CMD_MOUSE  --> HandleMouse
 |
 +-- CMD_KEY    --> HandleKey
```

以后项目继续增加功能，也可以继续在这里分派。

## 6. HandleMouse

客户端发送：

```text
Mouse {
    action;
    posXY;
    extra;
}
```

服务器收到后：

```text
Mouse
  ↓
判断 action
  ↓
SetCursorPos / SendInput
  ↓
Windows 真正执行
```

## 7. 为什么移动和点击分开

移动：

```text
SetCursorPos
```

点击：

```text
SetCursorPos
↓
SendInput
```

因为移动只是位置同步，而点击需要真正产生鼠标按键事件。

## 8. HandleKey

客户端发：

```text
KEY {
    virtual_code;
    key_status;
    ext_flags;
}
```

服务器转换成：

```cpp
INPUT input = {};
input.type = INPUT_KEYBOARD;
SendInput(...);
```

这里可以理解为：

```text
客户端键盘消息
      ↓
网络中的 KEY 数据
      ↓
服务器 KEY 数据
      ↓
Windows INPUT
      ↓
系统键盘事件
```

## 9. HandleScreen

这是服务端最复杂的函数。

完整链路：

```text
GetDC(NULL)
     ↓
拿到整个屏幕 DC
     ↓
CImage.Create
     ↓
BitBlt
     ↓
截图进入 CImage
     ↓
CImage.Save
     ↓
JPEG
     ↓
IStream
     ↓
多个 chunk
     ↓
send_packet
```

## 10. 为什么一定要 ReleaseDC

截图：

```cpp
HDC imageDC = image.GetDC();
BitBlt(...);
image.ReleaseDC();
```

这里的 `GetDC()` 可以理解成：

> “我要暂时拿到这张图片内部的画布。”

拿到后使用完必须：

```cpp
image.ReleaseDC();
```

否则后面的 CImage 操作可能触发断言。

这是本项目曾经实际遇到过的问题。

## 11. 为什么使用 JPEG

连续桌面截图的特点是：

```text
图片多
图片大
发送频繁
```

PNG 通常更适合无损图像，但桌面连续传输时数据可能更大。

本项目选择 JPEG 的主要目的：

```text
减少图片体积
↓
减少网络数据
↓
降低发送压力
```

## 12. 为什么要分块

一个 JPEG 可能远远大于一个很小的网络缓冲区。

因此：

```text
完整 JPEG
   ↓
切成 chunk 0
chunk 1
chunk 2
...
   ↓
客户端重新拼接
```

每块前面都有：

```text
总大小
块编号
总块数
宽
高
格式
```

客户端就知道如何重新组合。
