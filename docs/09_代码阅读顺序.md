# 09 代码阅读顺序——不要从第一行读到最后一行

如果是零基础，直接从第一行看到最后一行，很容易迷路。

推荐按下面顺序阅读。

## 第一次：只看全局结构

客户端只看：

```text
WinMain
winProc
RecvThread
InputThread
```

服务器只看：

```text
main
HandleCommand
HandleScreen
HandleMouse
HandleKey
```

先知道“谁调用谁”。

## 第二次：只看协议

找到：

```cpp
PacketHeader
Packet
CMD
Mouse
KEY
```

画出：

```text
[magic][cmd][body_len][body]
```

## 第三次：只看 TCP

重点：

```cpp
send_exact
recv_exact
send_packet
recv_packet
```

直到你能解释：

> 为什么不能简单地一次 send 对应一次 recv？

## 第四次：只看截图

服务器：

```cpp
HandleScreen
```

客户端：

```cpp
RecvThread
DisplayFrame
```

把完整链路画出来：

```text
屏幕
 ↓
CImage
 ↓
JPEG
 ↓
chunk
 ↓
TCP
 ↓
frameBuf
 ↓
CImage.Load
 ↓
窗口
```

## 第五次：只看鼠标

客户端：

```text
WM_MOUSEMOVE
 ↓
MapToServer
 ↓
PushMove
 ↓
InputThread
 ↓
SendMouse
```

服务器：

```text
recv_packet
 ↓
HandleMouse
 ↓
SetCursorPos / SendInput
```

## 第六次：只看键盘

客户端：

```text
WM_KEYDOWN
 ↓
Shift 特殊判断
 ↓
PushInput
 ↓
InputThread
```

服务器：

```text
HandleKey
 ↓
SendInput
```

## 第七次：最后才看优化

理解原理以后，再看：

```text
g_send_cs
g_latest_move
g_move_dirty
MOUSE_MOVE_INTERVAL_MS
TCP_NODELAY
JPEG
```

这样你不会觉得优化代码是“魔法”。
