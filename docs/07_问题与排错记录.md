# 07 项目问题与排错记录

这份文档故意按照“我第一次做项目时会遇到什么”的顺序写。

## 问题 1：`uint32_t` 报错

### 原因

`uint32_t` 来自：

```cpp
#include <stdint.h>
```

如果编译器找不到类型，先检查头文件。

### 记忆

```text
uint32_t = 无符号 32 位整数
```

## 问题 2：Windows 结构体重定义

曾经遇到：

```text
sockaddr
sockaddr_in
fd_set
timeval
hostent
```

重定义。

### 常见原因

Winsock 头文件和其他 Windows 网络头文件的包含关系不正确。

本项目采用：

```cpp
#define WIN32_LEAN_AND_MEAN
#include <winsock2.h>
#include <ws2tcpip.h>
#include <windows.h>
```

尤其注意：

```cpp
winsock2.h
```

应该在 `windows.h` 之前。

## 问题 3：`inet_ntoa` 警告

`inet_ntoa` 是旧接口。

本项目优先使用：

```cpp
inet_pton
inet_ntop
```

一个负责字符串 -> 地址，一个负责地址 -> 字符串。

## 问题 4：CImage 断言

曾经出现类似：

```text
CImage::GetDC()
```

相关断言。

### 根本原因

拿到了 CImage 的 DC 后没有及时：

```cpp
image.ReleaseDC();
```

正确模式：

```text
GetDC
 ↓
BitBlt
 ↓
ReleaseDC
 ↓
Save
```

## 问题 5：CImage::Save 参数

不要想当然写成“第三个参数传 JPEG 质量”。

当前代码使用：

```cpp
image.Save(stream, Gdiplus::ImageFormatJPEG);
```

也就是直接指定 JPEG 格式。

## 问题 6：客户端和服务端协议不一致

这是非常严重的问题。

例如一边：

```text
BUF_SIZE = 65536
JPEG
24 字节 chunk header
```

另一边：

```text
BUF_SIZE = 1024
PNG
12 字节 chunk header
```

那么：

```text
服务器理解的第一个字节
可能是客户端理解的第二个字段
```

最终表现可能是：

```text
magic 错误
图片错误
连接断开
```

解决方法：

> 协议修改必须客户端和服务端一起改。

## 问题 7：两个线程同时 send

客户端有：

```text
RecvThread -> 请求画面
InputThread -> 鼠标键盘
```

如果两个线程同时写同一个 TCP socket，而没有统一保护，就可能出现逻辑包交错。

本项目使用：

```cpp
CRITICAL_SECTION g_send_cs;
```

所有 `send_packet()` 写 socket 的动作都经过同一个临界区。

## 问题 8：WM_PAINT 后又跑到 WM_MOUSEMOVE

C/C++ 的 `switch` 不会自动停下来。

如果：

```cpp
case WM_PAINT:
    ...
case WM_MOUSEMOVE:
    ...
```

中间没有 `break` 或 `return`，就会继续向下执行。

这叫：

> case 穿透。

所以本项目已经在处理完成后：

```cpp
return 0;
```

## 问题 9：窗口关闭时返回值未定义

如果一个返回非 void 的函数执行到末尾没有 return，行为是不可靠的。

因此 `winProc` 最后有明确的：

```cpp
return 0;
```

## 问题 10：鼠标拖出窗口后坐标飞掉

问题来自：

```text
LOWORD / HIWORD
```

它们不适合这里的有符号鼠标坐标。

本项目改用：

```cpp
GET_X_LPARAM
GET_Y_LPARAM
```

## 问题 11：Shift 组合键不稳定

`VK_SHIFT` 本身不能区分：

```text
左 Shift
右 Shift
```

因此只对 Shift 做：

```text
扫描码
 ↓
MapVirtualKeyA
 ↓
VK_LSHIFT / VK_RSHIFT
```

## 问题 12：鼠标移动越来越卡

如果每条 `WM_MOUSEMOVE` 都立即 send：

```text
鼠标移动
↓
大量 TCP 小包
↓
服务器大量 SetCursorPos
↓
CPU / 网络 / 调度压力增加
```

解决：

```text
最新位置覆盖旧位置
+
10ms 限频
```

## 问题 13：画面越来越落后

错误：

```text
客户端不停 CMD_SCREEN
```

服务器来不及处理时，请求会排队。

本项目：

```text
请求一帧
 ↓
完整接收
 ↓
显示
 ↓
再请求
```

## 问题 14：不要一看到错误就改十处

推荐排错顺序：

```text
编译错误
 ↓
先修编译
 ↓
启动错误
 ↓
先修启动
 ↓
连接错误
 ↓
先修网络
 ↓
画面错误
 ↓
再看协议
 ↓
输入错误
 ↓
最后看 SendInput
```

一次只改一个主要问题，否则最后不知道究竟是哪一处起作用。
