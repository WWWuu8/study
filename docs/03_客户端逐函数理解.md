# 03 客户端逐函数理解

## 1. 客户端到底负责什么

客户端不是“服务器的附属品”，它主要负责三件事：

```text
① 显示服务器画面
② 捕获本地鼠标键盘
③ 把鼠标键盘发送给服务器
```

因此客户端天然有两个方向的数据：

```text
服务器 ---> 客户端：屏幕
客户端 ---> 服务器：鼠标/键盘
```

## 2. 为什么客户端需要线程

如果只有一个线程：

```text
窗口消息
   |
   +--> recv 等服务器画面
   |
   +--> send 鼠标
```

那么网络操作可能卡住窗口。

本项目拆成：

```text
主线程
 |
 +--> Windows 消息循环
 |
 +--> 鼠标/键盘消息

RecvThread
 |
 +--> 接收画面

InputThread
 |
 +--> 发送鼠标/键盘
```

## 3. WinMain：总管

`WinMain()` 可以看成整个客户端的总管。

执行顺序：

```text
初始化临界区
      ↓
初始化 GDI+
      ↓
创建窗口
      ↓
初始化 Winsock
      ↓
创建 socket
      ↓
connect
      ↓
创建 RecvThread
      ↓
创建 InputThread
      ↓
GetMessage 消息循环
      ↓
退出清理
```

## 4. winProc：窗口消息总入口

Windows 不会主动调用：

```cpp
handle_mouse();
```

而是不断把消息送给：

```cpp
winProc(...)
```

例如：

```text
移动鼠标
   ↓
WM_MOUSEMOVE
   ↓
winProc
```

按键：

```text
按 Shift
   ↓
WM_KEYDOWN / WM_SYSKEYDOWN
   ↓
winProc
```

所以 `winProc` 是理解客户端输入的关键。

## 5. MapToServer：为什么要映射坐标

假设客户端窗口：

```text
1000 x 640
```

服务器屏幕：

```text
1920 x 1080
```

鼠标在客户端：

```text
(500, 320)
```

大约应该对应服务器：

```text
(960, 540)
```

因此需要：

```text
客户端坐标
     ↓
比例换算
     ↓
服务器坐标
```

## 6. 为什么不用 LOWORD / HIWORD

如果坐标变成负数：

```text
x = -5
```

简单地取低 16 位后可能变成很大的无符号数。

所以本项目使用：

```cpp
GET_X_LPARAM(lParam)
GET_Y_LPARAM(lParam)
```

它能够正确处理有符号坐标。

## 7. PushInput：为什么按键要进队列

鼠标点击、键盘按键不能随便丢。

例如：

```text
Shift down
A down
A up
Shift up
```

顺序不能乱。

因此进入：

```text
g_queue
```

然后由 `InputThread` 顺序发送。

## 8. PushMove：为什么鼠标移动不一样

鼠标移动可能一秒产生几十、几百条消息：

```text
(100,100)
(101,100)
(102,101)
(103,101)
...
```

如果全部发送，网络压力很大。

而对于移动来说，真正重要的是：

> “现在鼠标在哪里？”

所以项目只保存最新位置：

```text
旧位置 -> 覆盖
旧位置 -> 覆盖
旧位置 -> 覆盖
最新位置 -> 等待发送
```

## 9. InputThread：真正发数据的人

UI 线程不直接：

```cpp
send_packet(...);
```

而是：

```text
UI线程
  ↓
PushInput / PushMove
  ↓
InputThread
  ↓
send_packet
  ↓
服务器
```

这样窗口更流畅，而且所有输入写 socket 的动作集中到一个线程。

## 10. RecvThread：画面接收者

它的逻辑非常值得背下来：

```text
请求一帧
   ↓
recv_packet
   ↓
收到多个图片块
   ↓
按照 idx 放回 frameBuf
   ↓
块数收齐
   ↓
DisplayFrame
   ↓
请求下一帧
```

注意：

**不是不停请求。**

而是：

```text
上一帧完成
   ↓
下一帧
```

这就是一种简单的流控。

## 11. DisplayFrame：JPEG 到窗口

服务器发来的是：

```text
unsigned char*
```

本质上是一堆 JPEG 字节。

客户端：

```text
内存
 ↓
IStream
 ↓
CImage.Load
 ↓
image
 ↓
WM_PAINT
 ↓
窗口
```

## 12. 最后再看 WinMain

等上面的函数都理解后，再回来看 WinMain，就会发现：

```text
WinMain 不是最难的。
```

它只是把前面所有模块串起来。
