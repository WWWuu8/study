# 远程控制项目——零基础学习路线大纲

> 适合：第一次接触 Windows Socket、TCP、线程、Windows 消息、截图和输入模拟的 C/C++ 初学者。
>
> 学习原则：**先能跑，再理解；先理解数据怎么走，再理解每个函数为什么存在；最后再做优化。**

## 一、我到底在做什么

这个项目不是一上来就写“远程控制”。把它拆开，其实只有四件事：

1. 客户端连接服务器。
2. 服务器把屏幕画面变成 JPEG 数据发给客户端。
3. 客户端把鼠标、键盘动作变成数据发给服务器。
4. 服务器把收到的数据还原成 Windows 的鼠标、键盘操作。

可以先记住这一张总图：

```text
                  TCP 连接
        +----------------------------+
        |                            |
        v                            v
+----------------+          +----------------+
|   客户端       |          |    服务器      |
| 控制端/显示端  |          | 被控制电脑     |
+----------------+          +----------------+
| 鼠标/键盘      | --数据--> | SendInput      |
| 远程画面显示   | <--JPEG-- | 屏幕截图       |
+----------------+          +----------------+
```

## 二、整个学习顺序

### 第 1 阶段：先认识 TCP

学习：

- socket 是什么
- IP 和端口是什么
- `socket()`
- `bind()`
- `listen()`
- `accept()`
- `connect()`
- `send()` / `recv()`
- `closesocket()`
- `WSAStartup()` / `WSACleanup()`

目标：能够解释“客户端为什么能找到服务器”。

对应文档：`01_从零开始搭建项目.md`

---

### 第 2 阶段：解决 TCP 粘包/拆包

这是本项目真正开始变复杂的地方。

必须理解：

```text
TCP 不是：
[一个 send] -> [一个 recv]

TCP 实际是：
一条连续的字节流

send(A) + send(B)
可能 recv 成：
[A的一半]
[剩下一半 + B的一部分]
[ B剩下部分 ]
```

所以项目设计了：

```text
[magic][cmd][body_len][body]
```

服务器和客户端都通过 `recv_exact()` 把固定长度的数据凑齐。

对应文档：`02_TCP协议_粘包拆包.md`

---

### 第 3 阶段：理解客户端

按照这个顺序读 `client.cpp`：

```text
WinMain
  |
  +--> GDI+ 初始化
  |
  +--> Winsock 初始化
  |
  +--> 创建窗口
  |
  +--> socket + connect
  |
  +--> 创建 RecvThread
  |
  +--> 创建 InputThread
  |
  +--> GetMessage 消息循环
```

然后再看：

```text
鼠标/键盘消息
      |
      v
    winProc
      |
      v
   输入队列
      |
      v
 InputThread
      |
      v
    TCP
```

对应文档：`03_客户端逐函数理解.md`

---

### 第 4 阶段：理解服务器

服务器最重要的入口是：

```text
main
 |
 +--> socket
 |
 +--> bind
 |
 +--> listen
 |
 +--> accept
 |
 +--> recv_packet
 |
 +--> HandleCommand
        |
        +--> HandleScreen
        +--> HandleMouse
        +--> HandleKey
```

对应文档：`04_服务端逐函数理解.md`

---

### 第 5 阶段：理解屏幕传输

服务器不能简单地：

```text
截图 -> send(image)
```

因为图片可能很大。

本项目采用：

```text
屏幕
  |
  v
CImage
  |
  v
JPEG
  |
  v
24 字节分块头 + JPEG 数据
  |
  v
多个 TCP 协议包
  |
  v
客户端重新拼接
  |
  v
CImage.Load()
  |
  v
窗口显示
```

对应文档：`05_屏幕截图与分块传输.md`

---

### 第 6 阶段：理解三个优化

本版本只重点做三个优化：

1. **只针对 Shift 的特殊处理**：区分左 Shift / 右 Shift。
2. **鼠标发送频率优化**：鼠标移动只保留最新位置，并限制到约 100Hz。
3. **服务器处理速度优化**：减少不必要内存清零、减少日志、使用 JPEG、TCP_NODELAY 和较大的 socket 缓冲区。

对应文档：`06_三项优化详解.md`

---

### 第 7 阶段：整理曾经遇到的问题

按照“问题 -> 原因 -> 修改 -> 为什么”来学习：

- `uint32_t` 相关错误
- `sockaddr` / `fd_set` 重定义
- `inet_ntoa` 警告
- `CImage::GetDC()` / `ReleaseDC()`

- TCP 粘包/拆包
- 两个线程同时 send
- 窗口消息 case 穿透
- `LOWORD/HIWORD` 负坐标问题
- Shift 无法区分左右
- 鼠标移动包太多
- 客户端/服务端协议不一致

对应文档：`07_问题与排错记录.md`

### 第 8 阶段：虚拟机测试

最后不要直接在真实工作电脑上折腾。

建议：

```text
宿主机
  |
  +---- 虚拟机 A：服务器
  |
  +---- 虚拟机 B：客户端
```

最少也可以：

```text
虚拟机：服务器
宿主机：客户端
```

测试顺序：

1. 两台机器互相 ping。
2. 服务器启动。
3. 客户端修改 `SERVER_IP`。
4. 客户端连接。
5. 测试画面。
6. 测试鼠标移动。
7. 测试左/右键。
8. 测试滚轮。
9. 测试普通键盘。
10. 测试左 Shift。
11. 测试右 Shift。
12. 测试 Shift+字母、Shift+数字。
13. 测试拖动窗口边缘后的鼠标坐标。
14. 测试断开连接。

对应文档：`08_虚拟机测试手册.md`

## 三、最终应该达到什么程度

不是要求把 1000 多行代码全部背下来。

而是看到：

```cpp
recv_packet(fd, &packet);
```

你能说出：

> “TCP 是字节流，所以先收固定长度的头，再根据 `body_len` 收 body，然后检查 magic 和命令。”

看到：

```cpp
PushMove(&pt);
```

你能说出：

> “鼠标移动频率太高，中间位置没必要全部发送，所以只保存最新位置，再由输入线程按固定频率发送。”

看到：

```cpp
HandleScreen(cfd);
```

你能说出：

> “服务器截图、编码 JPEG、分块，然后通过自定义协议发送给客户端。”

达到这个程度，这个项目就真正学会了。
